# 向量化使用说明 - 网络连接问题解决方案

## 🔧 已添加的功能

### 1. 批量处理机制
- **批量大小**: 每批处理 50 个文档块（可配置）
- **批次延迟**: 每批之间延迟 0.5 秒，避免请求过快
- **优势**: 避免一次性处理太多文档导致连接中断

### 2. 重试机制
- **重试次数**: 每个批次最多重试 3 次
- **重试策略**: 指数退避（2秒 → 4秒 → 8秒）
- **自动恢复**: 网络临时中断时自动重试

### 3. 错误恢复
- **交互模式**: 批次失败时询问是否继续
- **自动跳过**: 非交互模式下自动跳过失败批次
- **进度保存**: 已成功的批次会保存，不会重复处理

### 4. 进度显示
- **实时进度**: 显示当前处理的批次和总数
- **成功标记**: ✅ 表示批次处理成功
- **失败标记**: ❌ 表示批次处理失败

## ⚙️ 配置参数

在 `utils/embeding.py` 中可以调整以下参数：

```python
# 批量处理配置
BATCH_SIZE = 50  # 每批处理的文档块数量（建议 20-100）
RETRY_TIMES = 3  # 重试次数（建议 3-5）
RETRY_DELAY = 2  # 重试延迟（秒）
BATCH_DELAY = 0.5  # 批次之间的延迟（秒，建议 0.5-2）
```

### 参数调整建议

**网络不稳定时**：
- `BATCH_SIZE = 20` （减小批量大小）
- `BATCH_DELAY = 1.0` （增加延迟）
- `RETRY_TIMES = 5` （增加重试次数）

**网络稳定时**：
- `BATCH_SIZE = 100` （增大批量大小）
- `BATCH_DELAY = 0.3` （减少延迟）
- `RETRY_TIMES = 3` （标准重试次数）

## 🐛 常见问题处理

### Q1: 连接被远程主机关闭（ConnectionResetError）

**原因**: 
- 网络不稳定
- API 请求频率过高
- 防火墙或代理问题

**解决方案**:
1. 减小 `BATCH_SIZE`（如改为 20）
2. 增加 `BATCH_DELAY`（如改为 1.0）
3. 检查网络连接
4. 检查防火墙设置

### Q2: 某些批次处理失败

**处理方式**:
- **交互模式**: 会询问是否跳过失败的批次继续处理
- **非交互模式**: 自动跳过失败的批次

**恢复方法**:
- 重新运行向量化脚本
- 已成功的批次不会重复处理
- 只处理失败的批次

### Q3: 向量化速度慢

**优化方法**:
1. 增大 `BATCH_SIZE`（如改为 100）
2. 减小 `BATCH_DELAY`（如改为 0.3）
3. 检查网络速度
4. 考虑使用本地嵌入模型（HuggingFace）

## 📊 性能优化建议

### 1. 网络优化
- 使用稳定的网络连接
- 避免在网络高峰期运行
- 考虑使用 VPN 或代理

### 2. 批量大小优化
- **小批量（20-30）**: 网络不稳定时使用
- **中批量（50-70）**: 标准配置，平衡速度和稳定性
- **大批量（100+）**: 网络稳定时使用，速度最快

### 3. 延迟优化
- **高延迟（1-2秒）**: 网络不稳定时使用
- **中延迟（0.5-1秒）**: 标准配置
- **低延迟（0.3秒）**: 网络稳定时使用

---

## 💡 最佳实践

1. **首次运行**: 使用默认配置（BATCH_SIZE=50, BATCH_DELAY=0.5）
2. **遇到错误**: 减小批量大小，增加延迟
3. **网络稳定**: 可以增大批量大小，减少延迟
4. **大量文档**: 分批处理，避免一次性处理太多
5. **保存进度**: 已成功的批次会自动保存，可以断点续传
